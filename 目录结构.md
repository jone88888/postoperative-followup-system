> 技术栈：前端 Vue 3 + Element Plus ｜ 后端 Django + DRF ｜ 数据库 MySQL
> 项目阶段：MVP

### 后端说明
- `config/` 只放全局配置，不放业务逻辑。
- 每个业务域独立成 app（`users` / `bindings` / `tasks` / `submissions` / `notifications` / `statistics`），与需求文档 7.x 节一一对应。
- 全局权限、分页、响应封装统一放 `config/utils/`，避免各 app 重复。
- 上传文件统一进 `media/`，便于权限隔离。

### 前端说明
- `api/` 按后端模块拆分，`request.js` 统一处理 token 与错误。
- `views/` 按**角色**分目录（patient/doctor/admin），与角色权限一一对应，路由守卫按 `meta.roles` 控制。
- `layout/` 为不同角色提供独立布局，菜单通过 `config/menu.js` 配置驱动，避免硬编码。
- 任务题型（文本/数值/图片/单多选）抽象为 `TaskForm.vue` 与 `TaskAnswer.vue` 通用组件，对应后端 `TaskItem`。

## 四、模块与需求映射

| 需求文档章节 | 后端 app | 前端目录 |
|---|---|---|
| 7.1 用户系统 | `users` | `views/login`、各角色首页 |
| 7.2 医患绑定系统 | `bindings` | `views/doctor/BindingReview`、`views/patient/MyDoctor` |
| 7.3 随访任务系统 | `tasks` | `views/doctor/TaskCreate`、`views/patient/TaskList` |
| 7.4 任务反馈系统 | `submissions` | `views/patient/TaskDetail`、`views/doctor/SubmissionView` |
| 7.5 消息提醒系统 | `notifications` | `views/**/Notifications`、`store/notification.js` |
| 7.6 数据统计功能 | `statistics` | `views/doctor/Dashboard`、`views/admin/Dashboard` |

## 五、开发顺序建议（对应第 10 节实施计划）
